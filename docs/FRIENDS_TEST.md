> **현재 상태:** v1.6.0 Stable은 이미 실제 2·3인 시험과 사용자 확인을 반영해 배포됐습니다. 이 문서는 **새로운 환경·추가 인원·오류 재현에 사용할 점검표**이지, 완료된 실기 QA를 다시 미완료로 되돌리는 문서가 아닙니다. 기존 검증 결과는 [QA 보고서](QA_REPORT.md)와 [2·3인 실측 기록](qa/2026-11-14-v160-extended/three/README.md)을 우선합니다. 실제 8인·FPS·게임별 네트워크는 추가 미확인 항목입니다.

v1.6.0은 정식 경기 2~8명을 허용합니다. 2인에서 시작·승패·재접속을 확인할 수 있지만, **여러 헌터의 동시 제작·소집·화면별 추적은 최소 3명이 필요**합니다. 상한 검증에는 실제 8명이 필요합니다. 먼저 2인 기본 흐름, 이어서 3~4인 협동 기능, 마지막으로 8인 상한 시험을 별도 기록하세요. 자동 테스트와 1인 클라이언트 시험을 통과했더라도 아래 항목의 통과를 뜻하지 않습니다. 아래 표는 실행 계획이며, 결과를 기록하기 전에는 미검증입니다.

준비된 시험 사본에서 **30~45분 압축 점검**, 이후 **기본 설정으로 실전 한 판**을 권장합니다. 재료 준비와 포털·안전 발판 설치 시간은 압축 점검 시간에 포함하지 않습니다. 시험용 사본을 별도로 가져오고 기존 플레이 월드는 보존하세요. 새 경기·로비 초기화는 인벤토리·장비·경험치를 초기화하며 지형·상자·드래곤을 복원하지 않습니다.

## 준비와 시험 설정

- 모두 실제 게임 버전을 적고 같은 버전으로 맞춥니다. 호스트가 싱글 월드를 열어 친구를 초대합니다. 친구 PC에는 별도 애드온을 먼저 설치하지 않고, 입장 시 월드 리소스 팩 다운로드로 들어올 수 있는지 확인합니다.
- 러너 1명, 헌터 A·B·C를 정합니다. 각자 자기 화면을 보고 결과를 말합니다. 호스트 화면만으로 다른 사람의 카메라·알림·나침반 상태를 판정하지 않습니다.
- 시험 사본에는 넓은 평지, 작은 고립 발판, 안전한 네더·엔드 진입 장소를 준비합니다. 시험 재료와 소집서·수신기는 **경기 시작 후** 호스트가 공급해도 됩니다. 실제 채굴 난도는 실전 한 판에서 따로 판단합니다.
- 로비에서 `/mh:menu` → **게임 설정 · 기능별 ON/OFF**로 설정합니다. 경기 중 설정을 바꿔 시험하지 않습니다.

## 30~45분 압축 점검

각 행마다 `통과 / 실패 / 미실행`을 기록하세요. 한 단계라도 이상하면 그 상태와 각자의 화면을 남긴 뒤 다음으로 넘어갑니다. 불명확한 거래를 임의로 초기화해서 정상 결과처럼 기록하지 않습니다.

| 순서·예상 시간 | 함께 할 행동 | 확인할 결과 |
|---|---|---|
| 1. 초대·중단·재접속 · 4분 | 친구가 팩을 받아 접속합니다. 경기 시작 후 헌터 한 명이 나갔다 돌아오고, 모두 모인 뒤 호스트가 저장 종료·재실행합니다. | 친구에게 메뉴·아이템 외형이 보입니다. `참가자 이탈 시 자동 일시정지` ON에서 이탈 시 경기 시계가 정지하고, 복귀 후 관리자가 재개합니다. 호스트 재실행 후에도 역할·시간·진행도가 유지되며 임의로 새 라운드가 시작되지 않습니다. |
| 2. 공동 제작 · 6~8분 | 새 경기에서 2분 이전 제작법·제작을 시도합니다. 공개 후 헌터 둘이 `/mh:craft`로 제작 모드를 켭니다. 한 단계는 수량을 나누어 내고, 다른 단계는 두 사람이 같은 재료의 필요 수량 전체를 동시에 버립니다. 나머지를 순서대로 내 8분 전에 9단계를 완료합니다. | 공개 전에는 제작 불가. 제작법은 헌터에게만 공개됩니다. 나눠 낸 수량은 팀에 합산되고, 동시 투척 때 단계가 두 번 증가하거나 다음 단계로 잘못 적용되지 않습니다. 초과·순서 불일치 재료는 바닥에 남습니다. 모두 합쳐 정확히 9단계, 헌터마다 추적기 1개, 러너는 0개입니다. 제작 모드를 끈 뒤 버린 일반 아이템은 소비되지 않습니다. 다음 시험 중 8분을 지나도 추가 지급되지 않습니다. |
| 3. 개인별 추적·접근 경고 · 5분 | 헌터들이 서로 다른 방향을 보며 각자 추적기를 확인합니다. 러너가 네더로 이동한 뒤 그 안에서 다시 움직입니다. 같은 차원으로 돌아와 헌터 한 명이 100→90→60→40→10블록으로 접근하고, 다른 헌터는 멀리 둡니다. | 각 헌터의 회전에 맞게 바늘이 러너를 가리킵니다. 다른 차원에서는 러너 차원과 **마지막 위치**로 표시되며 네더 안 이동을 오버월드 실시간 좌표처럼 표시하지 않습니다. 접근 알림은 러너에게만, 가까운 헌터 기준으로 단계가 바뀝니다. 경계에서 앞뒤로 움직여도 도배되지 않습니다. 헌터를 다른 차원에 두면 감지하지 않습니다. |
| 4. 소집·수신기 · 8~10분 | 아래의 거리·지형 순서로 소집을 시험합니다. 이어서 같은 차원 헌터 전원이 있는 동안 러너가 수신기를 사용하고, 헌터 한 명이 다른 차원으로 간 상태에서도 사용합니다. | 소집 성공 때만 한 장 소비, 실패 시 보존. 같은 차원 대상들이 서로 겹치지 않는 안전 지점에 도착합니다. 수신기는 같은 차원 **각 헌터 화면**이 러너 방향으로 전환됐다 약 3초 뒤 돌아옵니다. 다른 차원 헌터는 알림만 받고 카메라가 바뀌지 않습니다. 가까운 곳의 녹색 광선은 약 8초, 재사용 대기는 30초입니다. |
| 5. 자동 지급·미접속 지급 · 4~5분 | 새 경기의 로비에서 자동 지급을 **4분**으로 줄이고, `① 기본 경기 / 지급품 → 참가자 이탈 시 자동 일시정지`를 잠시 OFF로 둡니다. 제작하지 않고 한 헌터는 4분 전에 나가고, 다른 헌터는 인벤토리를 채운 채 4분을 넘깁니다. 이후 복귀·빈 칸 확보·재접속을 합니다. | 미접속 헌터에게는 복귀 후 1개만 지급합니다. 꽉 찬 인벤토리는 기존 물건을 지우지 않고 지급 대기하며, 빈 칸을 만든 뒤 1개만 받습니다. 재접속이나 추적기 분실로 무한 재지급되지 않습니다. 이 시험 종료 후 자동 일시정지를 **ON으로 복원**합니다. |
| 6. 처치·전적 · 5~7분 | 짧은 별도 경기에서 참가 헌터의 근접 공격과 투사체로 각각 러너를 처치합니다. 가능하면 투사체를 쏜 헌터가 나간 직후 명중하는 경우도 시도합니다. | 야생 부활이 남아 있어도 헌터 처치로 실제 사망하면 헌터 승리로 끝나고 전적이 한 번만 반영됩니다. 이탈 시 자동 정지 때문에 투사체 사망 자체가 발생하지 않았다면 이탈 처치 시험은 **미재현**으로 기록합니다. 조건을 바꿨다면 바꾼 설정도 함께 적습니다. |

### 소집 순서: 실패를 먼저, 성공은 두 번

1. 같은 높이의 넓은 평지에서 러너를 `(0.5, Y, 0.5)`, 소집 사용자를 `(350.5, Y, 0.5)`에 둡니다. **정확히 350블록은 거부**되어야 합니다. 350보다 가까운 경우도 확인합니다. 다른 헌터는 멀리 둡니다.
2. 사용자가 러너로부터 351블록 이상 떨어지게 합니다. 사용자만 설 수 있는 작은 고립 발판이나 주변이 용암인 곳에서 사용해 전원 이동 취소·소집서 보존을 확인합니다. 안전 공간이 다른 쪽에 남아 있으면 소집이 성공할 수 있으므로 시험 지형을 먼저 확인하세요.
3. 넓은 평지에서 첫 소집을 성공시킵니다. 같은 차원의 살아 있는 다른 헌터 **전원**이 이동하고, 러너와 사용자는 이동하지 않아야 합니다. 사용한 한 장만 사라집니다.
4. 곧바로 다른 헌터가 자기 소집서를 사용합니다. **팀 공용** 대기로 거부되어야 합니다. 한 헌터가 재접속해도 사용 횟수·대기가 초기화되지 않아야 합니다.
5. 30초 후 두 번째 소집을 성공시킵니다. 4인 시험이면 한 헌터를 다른 차원에 두어 그 사람은 알림만 받고 그대로 있는지 확인합니다. 3인 시험에서 다른 유일한 헌터가 다른 차원에 있다면 이동 대상이 없어 취소·아이템 보존되는 것이 맞습니다.
6. 대기가 끝난 뒤에도 세 번째 사용은 팀 횟수 2회 제한으로 거부되어야 합니다. 미완료 복구가 생기면 호스트의 **중단된 소집 복구** 메뉴에서 먼저 재시도합니다. 현재 위치 유지로 정리할 때는 전원이 안전한 곳에 있는지와 안내 내용을 확인하고, 그 사례는 정상 소집 성공과 따로 기록합니다.

## 기본 설정으로 실전 한 판

시험용 `공개 2 / 자동 4~8분`, `소집 대기 30초`를 각각 **20 / 40분, 300초**로 복원합니다. 자동 일시정지도 ON인지 확인하세요. 3~4명이 같은 월드에서 진행하며 다음을 관찰합니다.

- 러너의 야생 사망 두 번까지 경기가 이어지고, 각 부활 때 체력이 가득 차는지 확인합니다. 세 번째 야생 사망은 추가 부활 아이템을 사용하지 않았다면 헌터 승리입니다. 드래곤 승리까지 진행하려는 경기에서는 세 번째 야생 사망 시험을 하지 않습니다.
- 러너가 살아 있는 상태에서 엔더 드래곤을 처치하면 전원에게 러너 승리가 표시되고, 종료 후 추적기 지급·제작 시계가 더 진행되지 않는지 확인합니다. 헌터 승리·러너 승리 양쪽을 한 판에 확인할 수는 없으므로 미확인 결말은 다음 판 항목으로 남깁니다.
- 경기 종료 후 로비 초기화와 다음 경기 시작을 확인합니다. 이전 제작법·단계·소집 사용 횟수가 새 경기에 섞이지 않고 누적 전적은 보존되어야 합니다. **새 드래곤과 새 지형이 필요하면 `.mcworld`를 새로 가져옵니다.** 초기화로 드래곤이 되살아난다고 기대하지 마세요.
- 가능하면 60분 이상 플레이하며 호스트와 친구 각각의 입력 지연, 블록 반응, 추적기 갱신, 재접속 후 지연, 카메라 원상복귀를 관찰합니다. 실제 FPS/TPS 도구로 측정하지 않았다면 숫자나 성능 개선율을 기록하지 말고 발생 시간·상황·지속 시간으로 남깁니다.
- 기본 20분 제작법 공개와, 직접 제작하지 못한 경기의 40분 자동 지급은 각각 실제 경기 시계로 확인합니다. 40분 전에 제작했다면 그 판에서는 **40분 중복 지급 없음**만 검증한 것입니다.
