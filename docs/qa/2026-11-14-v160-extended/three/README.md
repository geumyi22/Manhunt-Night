# v1.6.0 THREE — 실제 3인 후속 QA

**실제3인으로 두 라운드를 마치고 저장 종료한 후속 QA입니다.** 확인한 기능과 직접 관찰·사용자 보고·상태 로그의 범위를 구분합니다. 남은 복합 항목과 FPS 미측정 때문에 전체 E2E·성능 통과나 Stable 승격으로 판정하지 않습니다. 공개 자료는 계정명·개인 경로를 제외한 상태/투척 표본과 기능별 근거, 두 메모리 수집창 및 최종 분석입니다.

## 환경·설정과 범위

별도 `QA v1.6.0 THREE PLAYERS` 사본에서 Windows PC 두 대와 휴대폰 한 대, 각각 다른 계정으로 정식3인 경기를 시작했습니다. 호스트 PC와 휴대폰이 헌터, 다른 PC가 러너이며 중간 로그도 `practice=false`, `rosterSize=3`, 헌터2명·러너1명을 기록합니다. Bedrock26.63은 PC 실행 환경과 휴대폰 사용자 확인을 구분합니다. LONG의 접속3명/경기2명 상태와 다른 새 경기입니다.

| 설정 | THREE 기능 시험 | 원래 기본값·복원 확인 |
|---|---:|---|
| 제작법 공개 |2분|20분 — 종료 후 시험 사본 복원 확인|

시간 가속이나 가상 참가자는 사용하지 않았습니다. 단축 설정은 시험 사본 UI에서 적용한 기능 검증 조건입니다. 기본20/40분을 실제 경과한 [LONG 시험](../long/README.md)과 합치지 않습니다. 재료·수신기·소집서·장비 지급, 위치와 발판·조명 준비, 차원 이동은 명령으로 수행한 조건을 기록합니다. 자연 채집·제작대 조합·포털 통과를 시험한 것으로 표시하지 않습니다.

시험 사본에는100틱 상태 관찰과 실제 아이템 투척/생성 이벤트 관찰만 추가했습니다. 게임 상태·시간·설정·인벤토리에 쓰지 않는 코드인지, 원본 팩 코드가 정확한 접두부로 유지되는지 사전 비교했습니다. [실행 사본 대조](installed-probe-reference-audit.json)와 [독립 감사](independent-audit.json)에 검증 방법·한계가 있습니다. 관찰 콜백·인벤토리 읽기·로그 비용은 게임 성능과 분리해서 측정하지 않았습니다.
