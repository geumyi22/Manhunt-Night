# v1.6.0 LONG — 실제 2인 기본20/40분 후속 시험

2026-11-14 KST. 별도 `QA v1.6.0 LONG 40MIN` 사본에서 Windows Bedrock26.63 PC 두 대로 실행했습니다. 호스트는 헌터, 다른 PC는 러너입니다. 뒤늦게 휴대폰 계정이 연결되어도 경기 명단은 **러너1명·헌터1명, 총2명**으로 유지되었습니다. 휴대폰26.63 버전은 사용자 확인입니다. 이 자료는3인 경기나 다중 헌터 E2E의 완료 근거가 아닙니다.

기본 공개20분·자동지급40분·야생 부활2회·최대3회·자동일시정지를 유지했고, 경기 시계를 가속하거나 가상 참가자를 추가하지 않았습니다. 시험 사본에만100틱 간격의 읽기 전용 관찰 코드를 추가했습니다. 코드 자체는 아래에 공개하며 배포 팩에는 포함하지 않습니다. 명령으로 낙하 위치·시험 물품·발판/조명을 준비했고, 적대 몹 피해·헌터 사망·긴 정지 대기·UI 조작·재접속·월드 재실행이 섞인 기능 시험입니다. 실제 탐험만으로 구성된 부하 시험이나 통제된 비교 벤치마크가 아닙니다.

## 종료된 측정 결과

정상 관찰 JSON은 **666행, 관찰 세션3개**입니다. 세션마다 첫 표본을 제외하고, 연속 번호·단조 시각·실제 경과시간을 확인한663개 구간을 집계했습니다. 최종 스냅샷에는 잘린 행이나 형식 오류가 없습니다. 세션 간 저장/로드 공백은 보간하지 않았고, 같은 경기의 누적 시계1452·2479·2686초를 합산하지 않았습니다.

TPS는 `합계 elapsedTicks × 1000 / 합계 elapsedMs`입니다. 프레임률이 아니며, 일시정지 상태에서도 엔진 관찰 틱은 진행됩니다.

| 집계 | 유효 관찰시간 | 시간가중 TPS |
|---|---:|---:|
| 로비·일시정지·상태 전환·종료 후 포함663구간 전체 |3324.242초|19.9444|
| 정식 경기 배정부터 첫 승리 관측까지613구간, 일시정지·전환 포함 |3074.242초|19.9399|

**최저7.0771 TPS(100틱/14.130초)**는 지급 후 두 번째 재실행 직후,20:09:20.821→20:09:34.951 KST에 관찰됐습니다. 양끝 모두paused·접속1명 상태이며 원인은 미확정입니다. 이 구간을 제외한 수치만 제시하거나 제품 결함·성능 개선으로 단정하지 않습니다. 전체 값은 저장/로드 공백을 제외한 여러 관찰 세션의 합계이며 연속 무중단 측정은 아닙니다.

호스트 `Minecraft.Windows` 프로세스 메모리/CPU는2초 간격을 요청하여 **1572표본**, 첫 표본19:22:42.244 KST부터 마지막20:15:31.670 KST까지 **3169.426초**를 확보했습니다. 수집기 실행시간3171.463초와 표본 간 시간범위는 다릅니다. 월드 재실행 화면·접속1/2/3명·유예/진행/일시정지/종료가 함께 포함됩니다.

- Working Set: 중앙 **2319.19 MiB**, 최대 **2422.52 MiB**.
- Private Bytes: 중앙 **4686.65 MiB**, 최대 **4930.33 MiB**.
- 논리 프로세서20개 전체를100%로 둔 시간가중 CPU: **19.35%**.

메모리 중앙값은 짝수 표본의 가운데 두 값을 평균한 최종 분석값입니다. [수집기 원래 요약](sanitized-memory-summary.json)은 아래쪽 중앙값을 사용하므로 마지막 소수가 다를 수 있습니다. CPU는 유효한 각 구간의 `cpu_percent_machine × interval_s` 합계를 해당 시간 합계로 나눴습니다. Working Set과 Private Bytes를 더하지 않으며 다른 PC·휴대폰·GPU의 사용량으로 해석하지 않습니다. 메모리 누수 부재나 특정 인원 성능 합격을 주장하지 않습니다.

기존 호스트 환경은 i5-13600KF·RTX3070·RAM 약32GiB이며 기존 셰이더·영상 설정·배경 작업을 통제하지 않았습니다. 관찰 코드의100틱 콜백·인벤토리 읽기·로그 비용도 분리하지 않았습니다. 앞선 약11분 경기/약3분 메모리 측정과 합산하거나 개선율을 계산하지 않습니다.

## FPS·네트워크와 남은 검증

**FPS와 게임별 네트워크는 미측정**입니다. [실제 측정 차단 기록](metrics-capability-summary.json)에 이번 실행 중 PresentMon의 두 옵션 형태 모두 종료코드1·CSV없음·프레임0개, PktMon 드라이버 접근 거부, FrameView 서비스 시작/중지 권한 요청 거부를 기록했습니다. 내부 원인을 확정하지 않았으며 서비스·권한·보안 설정을 변경하지 않았습니다. TPS·메모리·프로세스I/O를 FPS·게임 대역폭/지연/손실률로 대체하지 않습니다.

직접9단계 제작 후 자동시점 중복 방지, 여러 헌터의 추적기·동시 투척/공유 제작·소집 성공/쿨다운/횟수/복구·차원 이동·기기별 수신기 카메라/광선·드래곤 승패·8인 상한은 이 자료로 완료 처리하지 않습니다. 접근 경고의 쿨다운도 미측정입니다. 별도3인 시험 자료가 추가될 경우 이2인 기본20/40분 시험과 구분합니다. **Pre-release와 Issue #3 Open을 유지합니다.**

- [summary.json](summary.json): 세션·상태별 TPS, 전환·제외 기준, 메모리 분석.

- [host-memory.csv](host-memory.csv), [sanitized-memory-summary.json](sanitized-memory-summary.json): 호스트 프로세스 원시 수치와 개인 경로/PID를 제거한 수집기 요약.
- 자동지급·두 재실행 JSON은 당시의 중간 스냅샷이며 수정하지 않았습니다. 그 파일의 `captureClosureReported=false`·미완성 꼬리행은 당시 상태입니다. 최종666행의 오류0개·종료완료와 구분합니다.
- [qa-probe-fragment.txt](qa-probe-fragment.txt): 시험 사본에만 추가한 관찰 코드. 이름은 명단 인덱스로 변환하고 결과는 고정 승리 문구입니다. 배포 기능이나 독립 실행 모듈이 아닙니다.
- [SHA256SUMS.txt](SHA256SUMS.txt): 이 README와 공개 자료11개의 바이트 해시. 해시 파일 자체는 포함하지 않습니다.

원본 Content Log·계정명이 보이는 스크린샷·설치 월드 위치·개인 진단 파일은 공개하지 않았습니다. JSON의 로컬 스크린샷 이름/해시는 해당 이미지 공개를 뜻하지 않습니다. 자료는 승인된 공개 후보 원문 바이트를 보존했고 줄바꿈 정규화도 하지 않았습니다.

SHA-256을 계산해 목록과 비교하고, JSONL에서 세션 첫 행을 제외한 연속 구간의 경과 틱/시간을 위 공식으로 재계산할 수 있습니다. 공개 샘플의 세션 구분·시간·인원 필드를 유지해야 하며 재실행 경계 간 구간을 만들지 않습니다. CSV는 첫 행의 CPU 공란을 제외하고 위 가중식과 `bytes / 1048576`을 적용합니다. 공개 디렉터리에 실행 도구를 추가하지 않았으며 기존 원본 로그가 있어야만 검증 가능한 것으로 설명하지 않습니다.
