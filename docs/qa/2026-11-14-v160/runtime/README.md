# v1.6.0 실제 2인 정식 경기 관측 자료

2026-11-14 KST. 호스트 UI에서 저장 및 종료 후 월드 목록 복귀를 확인한 뒤 추출한 스냅샷입니다. 별도 QA 사본의 읽기 전용 관찰 도우미를 사용했으며, 배포 게임 코드에 도우미를 추가하지 않았습니다.

## 범위와 결과

- 같은 Content Log에 들어 있는 v1.5.1 행을 제외하고, `rosterSize` 필드가 있는 v1.6.0의 완전한 JSON **169개**만 추출했습니다. 마지막 완전한 관측 시각은 **19:05:23.222 KST**입니다. 원본 로그 전체와 개인 경로·닉네임은 포함하지 않았습니다.
- `practice=false`, `rosterSize=2`, `onlineRoster=2`, `hunters=1` 및 유예→진행 상태가 관측됐습니다. 기존 버전의 늦은 접속 1인 연습과 달리 **실제 2인 정식 경기의 참가 상태**입니다. 모든 기능의 E2E 통과를 뜻하지 않습니다.
- 참가자 이탈 시 `onlineRoster=1`, `phase=paused`, 경기 시계 115초가 관측됐습니다. 재접속 후 참가자 2명이 복구됐어도 일시정지는 유지됐으며, 이후 진행 상태로 돌아왔습니다. 로그만으로 재개 동작의 주체나 자동 재개를 확정하지 않습니다.
- 사용자에게 헌터 출발·재접속·수신기 카메라 약 3초 전환 및 복귀·다이아몬드 검 직접 처치 성공을 확인받았습니다. 상대 클라이언트의 화면을 에이전트가 직접 검사한 결과와 구분합니다.
- 호스트 화면에는 러너의 피살과 헌터 승리·경기 시간 10:21이 표시됐습니다. 관찰 로그에는 `ended`, `matchSeconds=621`, 익명화한 승수 배열 `[1]`이 남았습니다. 승수는 이름을 제거한 카운터이므로 그 자체만으로 처치 원인·승리 팀을 특정하지 않습니다.

## TPS와 성능 한계

TPS는 100틱 관찰 구간마다 엔진 틱 차이를 벽시계 경과 초로 나눈 값입니다. 가중 평균은 합계 틱 ÷ 합계 초이며, 프레임률이 아닙니다.

| 집계 | 유효 시간 | 가중 평균 TPS |
|---|---:|---:|
| 2인 유예/진행 상태가 양끝에서 유지된 구간만 | 615.049초 | 19.9984 |
| 참가자 배정 후 첫 경기 종료 관측까지, 이탈·일시정지·재접속 전환 포함 | 680.941초 | 19.6787 |
| 같은 참가자 상태를 유지한 종료 후 구간까지 포함 | 725.978초 | 19.6976 |

**이탈·일시정지 전환 구간에서는 100틱이 15.817초에 진행되어 6.3223 TPS가 관측됐습니다.** 시각은 18:55:28.067 KST입니다. 원인은 확정하지 않았습니다. 전환을 제외한 약 20 TPS만으로 전체 실행이 안정적이었다고 표현하지 않습니다. 포커스·게임 일시중단·호스트 처리 지연·벽시계 영향 등을 이 기록만으로 분리할 수 없습니다.

메모리는 호스트 프로세스만 **180.839초, 178개 샘플**을 측정했습니다. 접속 1/2명, countdown/grace/running/paused가 혼합된 시간창입니다. 참가자 명단 2명과 `practice=false`는 유지됐지만 접속 중 참가자는 이탈 동안 1명으로 줄었습니다.

- WorkingSet: 중앙 **2849.05 MiB**, 최대 **2893.59 MiB**.
- Private Bytes: 중앙 **4588.81 MiB**, 최대 **4860.65 MiB**.
- 전체 논리 프로세서 20개를 100%로 둔 시간가중 CPU: **26.32%**.

표의 중앙값은 원시 CSV에서 다시 계산했습니다. 최초 sampler JSON의 하위 중앙값도 원문 그대로 보존하여 일부 마지막 소수값이 다를 수 있습니다. WorkingSet과 Private Bytes를 더하지 않으며, GPU·상대 클라이언트 사용량으로 해석하지 않습니다. 인원별·버전별 성능 개선이나 메모리 누수 부재를 주장하지 않습니다.

**FPS와 게임 네트워크는 미측정**입니다. 수신기 카메라나 접속 성공이 FPS·지연·대역폭 측정은 아닙니다. 실제 역할별 추적기, 동시 투척 제작, 소집, 차원 이동, 추가 부활·투사체·드래곤 승리, 다수 인원 및 장시간 실기는 이 자료만으로 완료 처리하지 않습니다.

## 재현과 파일

- `tps-samples.jsonl`: 닉네임 없는 원시 v1.6.0 QA 행.
- `official-two-player-memory.csv` / `.json`: 실제 호스트 메모리·CPU 측정 원문.
- `summary.json`: 위 자료의 계산 결과와 상태 전환 시각. `sessionClosureReported=true`는 게임 UI 종료 확인을 전달받았다는 의미입니다.
- `observations.json`: 사용자 보고·호스트 UI·관찰 코드 지표를 분리한 기록.
- `probe-world.json`: 배포 입력 해시, 독립 UUID와 관찰 도우미를 사용한 사본 생성 기록. 원본 DB/입력 보존 검사는 사본 생성 시점의 검사입니다.
- `qa-probe-fragment.txt`: 실제 시험 사본의 `main.js` 끝에 추가한 읽기 전용 코드. 독립 실행 모듈이나 배포 기능이 아닙니다.
- `measure-minecraft-process.ps1`: PID 지정 메모리·CPU 수집기. 기존 출력이 있으면 덮어쓰지 않습니다.
- `analyze-v160-metrics.mjs`: 계산을 재현하는 Node.js 분석기. 개인 절대 경로가 없고, 보존 파일과 다른 새 출력 폴더가 필수입니다.
- `SHA256SUMS.txt`: 공개 증거 및 측정 도구의 해시.

Node.js 22 이상에서 다음처럼 공개된 JSONL/CSV로 계산을 재현합니다. `--out`을 생략하거나 출력 폴더에 기존 파일이 있으면 중단합니다.

```text
node analyze-v160-metrics.mjs --out <새로운-빈-출력폴더> --closed
```

선택적으로 `--evidence <증거폴더>`와 `--log <개인-원본로그-또는-QA-JSONL>`를 지정할 수 있습니다. 기본 입력은 동봉된 개인정보 없는 JSONL입니다. 이 입력으로 재현하면 원본 로그에서 제외했던 이전 버전 행 수·로드 메시지·잘린 행 같은 출처 정보는 달라질 수 있지만 TPS와 메모리 계산은 동일해야 합니다. 이번 공개본에서도 실제로 재계산하여 수치 일치를 확인했습니다.
