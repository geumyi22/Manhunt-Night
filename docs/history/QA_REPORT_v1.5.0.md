## 3. 기술적 제한과 적용한 대안

**나침반은 정식 API의 바닐라 나침반 목표 변경 기능을 사용하지 않습니다.** 확인한 안정 API에는 해당 목표 설정 기능이 없어 자체 제작한 32방향 픽셀 이미지를 플레이어별 상대 방위로 선택합니다. 프레임 선택의 수학적 최대 오차는 5.625도이며, 16×16 이미지의 픽셀 모양과 회전 감각은 바닐라 연속 회전과 다릅니다. 실제 손·핫바에서 동쪽 목표를 남쪽을 바라보는 플레이어의 왼쪽으로 표시하는 것을 확인했습니다. 인벤토리 전체 프레임·모든 시선 각도·멀티플레이 렌더링은 미검증입니다.

**투척 제작은 준비 기록을 저장한 뒤 소비하지만 강제 종료까지 원자적인 트랜잭션은 아닙니다.** 아이템 엔티티·인벤토리·월드 상태를 동시에 디스크에 확정하는 API가 없어 결과가 불확실한 거래는 중단하고 관리자 확인을 요구합니다. 사라진 엔티티를 소비 완료로 추정하거나 자동 환불·재지급하지 않습니다. 26.63에서 실제 Q 투척의 spawn→drop 이벤트가 같은 틱에 발생했습니다. 최초 실행에서 네이티브 목록 순회 오류를 발견해 인덱스 순회로 수정한 뒤, 실제 9단계 소비·지급을 재확인했습니다. 합쳐진 아이템 등 확인할 수 없는 투척은 보존합니다.

**소집 위치 검사는 보수적입니다.** 정식 API에서 확정적으로 사용할 수 없는 충돌 형상 판정을 가정하지 않고, 알려진 안전한 바닥·발과 머리 공간·주변 위험을 검사합니다. 실제로 서 있을 수 있는 특수 블록도 제외될 수 있습니다. 안전한 전원 배치가 불가능하면 소집서를 보존하고 취소합니다. 실패 복구가 남아 있으면 다음 소집과 초기화를 막습니다. 원위치 청크를 읽지 못할 때 관리자 메뉴에서 재시도하거나, 일시정지·전원 생존·안전 위치 확인 후 현재 위치 유지로 실패 거래를 정리할 수 있습니다. 부활 거래 역시 표식·저널·관리자 확인으로 처리하며 불명확한 아이템을 자동 생성하지 않습니다.

**소집서 획득 OFF는 등록된 작업대 제작법 자체를 실시간 제거하지 못합니다.** 설정에 따라 사용을 막고 아이템을 보존하지만 정적 제작법은 남습니다. OFF 상태에서 제작하면 이미 제작대에서 사용한 재료가 자동 반환되지는 않습니다. 사용자가 설정 효과를 오해하지 않도록 이 범위를 안내해야 합니다.

재료 후보의 획득 방법·난도와 API·라이선스 근거는 [API_RESEARCH_v1.5.md](API_RESEARCH_v1.5.md)를 참고합니다. 모든 시드에서 20분 안에 어려운 재료 6개씩을 확보할 수 있다고 보장하지 않으며, 40분 자동 지급과 수량 설정이 탐색 편차를 완화합니다.

**요새 안내·도착 판정은 제공 월드의 기반 시드에 한정됩니다.** `FORTRESSES`와 요새 영역 데이터는 고정값이며 다른 시드에 대한 자동 탐색·검증 기능이 없습니다. 다른 월드에 애드온을 적용할 때는 요새 힌트를 OFF로 설정해야 합니다. 다른 시드에서 이 기능을 지원하거나 검증했다고 주장하지 않습니다.

## 4. 실제 클라이언트 확인과 남은 검사

실제 게임 화면은 26.63, 설치 패키지는 1.26.6301.0입니다. 격리한 테스트 월드에만 검사 도우미를 붙여 20분 대기와 재료 수량을 줄였으며, 배포 팩·월드에는 도우미가 포함되지 않습니다. 실제 Q키로 조약돌 2개를 나누어 버려 0/2→1/2→다음 단계로 진행한 뒤 9단계까지 완료했습니다. 바닥에 이전부터 남아 있던 아이템은 소비하지 않았습니다. 추적기 1개 지급, 손/핫바의 빨간 바늘 왼쪽 표시, 토템 우클릭 후 기회 2→3 및 아이템 소비를 관찰했습니다. 이 시험은 실제 20분 서바이벌 수급·여러 헌터 동시 참여를 시험한 것은 아닙니다.

검사 도우미가 없는 배포용 `.mcworld`도 Minecraft의 **세계 가져오기**에서 직접 가져왔습니다. 새 월드의 BP 52개·RP 40개 파일이 배포 파일·소스와 바이트 단위로 일치하는 것을 확인했습니다. 로비, `/mh:menu`, 기존 설정 카테고리와 신규 추적 상세 페이지, 20/40분 기본값이 표시됐습니다. 1인 연습에서 5초 카운트다운, 야생 출발, 60초 도주 유예와 종료 시 버프 아이콘 해제, 가득 찬 체력 두 줄, 기본 야생 부활 2회를 관찰했습니다. 최종 부활 저널 코드로 토템 사용 시 아이템 1개가 사라지고 3회로 증가했습니다. `/damage @s 100 fall`로 낙하 원인의 사망 이벤트를 발생시켜 1회 차감·즉시 부활·체력 두 줄 완전 회복·경기 지속을 확인했습니다. 실제 높은 지형에서 떨어지는 이동 과정까지 시험한 것은 아닙니다. 앱을 종료한 뒤 재입장하면 경기가 일시정지 상태로 복원됐습니다.

- 실제 26.62 클라이언트 및 3~4인 친구 초대: 미검증.
- 전체 차원 이동, 드래곤·사망 승패, 4단계 경고, 여러 헌터 소집·rollback의 실제 다중 기기 E2E: 미검증. 해당 경로는 모의 통합 테스트로 검사했습니다.
- 20/40분 실제 장시간 플레이, 월드 강제 종료/정전, 엔진의 디스크 저장 순서: 미검증.
- FPS/TPS 실측 및 전후 비교: 미실시. 나침반은 5틱에서 2틱 표시로 응답 빈도가 증가했습니다. 캐시·프레임 변경 시 쓰기·비활성 건너뛰기·변화 없는 저장 생략을 적용했으나 성능 향상 수치로 표현하지 않습니다.
- 원본 월드의 과거 실험 사용 이력은 보존했습니다. 활성 실험 옵션을 끈 출력에서도 게임에 실험 이력 경고가 표시됩니다. 스크립트는 안정 API만 사용합니다.

### 팩 경고와 셰이더 분리 시험

26.63에서 빨간 “하나 이상의 리소스 팩 또는 행동 팩을 불러오지 못했습니다” 메시지가 표시됐습니다. Manhunt BP/RP의 게임 내 기술 정보는 모두 “오류가 발견되지 않았습니다”였고, 검사한 콘텐츠 로그에 팩·스크립트 오류는 없었습니다. 신규 명령어의 바닐라 `recipe` 별칭 충돌은 `/mh:trackerrecipe`로 변경했습니다. 이 충돌을 없앤 시험 사본에서도 빨간 메시지는 남았습니다.

사용자 요청에 따라 설치된 셰이더 3종(BSLB Dreamy, Prizma, Solar)을 별도 백업 폴더로 옮기고 해당 글로벌 활성 항목을 해제했습니다. 앱을 완전히 재시작해도 경고가 남았습니다. 이어 게임 UI에서 **새 바닐라 월드**를 만들고 활성 리소스 팩 없음·활성 행동 팩 없음·기본 글로벌 텍스처만 사용 중임을 확인했으며, 이 월드의 채팅에서도 같은 빨간 메시지를 직접 재현했습니다. 따라서 이 메시지만으로 Manhunt 또는 셰이더의 로딩 실패라고 판단하지 않습니다.

공식 [MCPE-241656](https://bugs.mojang.com/browse/MCPE-241656)에도 팩 없는 월드에서 같은 경고가 나타나는 증상이 Confirmed/Open으로 기록돼 있습니다(2026-11-08 확인). 공식 영향 버전 목록에는 26.63이 없으므로 현재 PC의 내부 원인까지 확정한 것은 아닙니다. 경고는 여전히 표시되며 숨기거나 해결했다고 주장하지 않습니다. 셰이더 백업 및 다른 기존 월드는 배포 소스에 포함하지 않았습니다.

## 5. 배포 판정
