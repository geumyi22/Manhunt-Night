## 2. v1.5.1 변경과 자동 검증

- **나침반 원본 외형:** Mojang의 고정 버전 `compass_atlas.png`에서 16×16 셀 32개를 확대·재색칠 없이 추출했습니다. 원본 자체의 중복을 포함해 서로 다른 픽셀 이미지는 28개입니다. 모든 출력 프레임을 원본 셀과 픽셀 단위로 비교하고, 원본 해시·출처 고지와 동서남북의 바늘 방향을 검사했습니다. 이전 보고서의 자체 제작 이미지 32개 설명은 v1.5.1에 적용하지 않습니다.
- **경계·광선 반복 실행:** `currentTick % 10` 조건이 등록 시점과 맞지 않으면 모든 호출을 건너뛰는 오류를 실제 경계 시험에서 발견했습니다. 다음 실행 시각을 별도로 관리하도록 수정했습니다. 등록 시점 0~9, 독립적인 경계·광선 실행 간격, 같은 틱 중복 실행, 지연 후 몰아서 실행하지 않는 동작, OFF·재활성화·일시정지·리셋을 5개 자동 검사로 추가했습니다. 수정 후 실제 X=6000 이동 시험의 안전 지점 복귀와 수신기 우클릭의 광선 생성·약 8초 뒤 해제를 재확인했습니다. 여러 헌터의 카메라 전환은 아직 미검증입니다.
- **카운트다운·경기 시계:** 시작 시점부터 100틱을 채운 뒤 러너가 출발하고, 이후 20틱마다 경기 시간이 증가하도록 보완했습니다. 실행 중 일시정지·재개 때는 다음 초까지 남은 부분 틱을 보존합니다. 월드를 다시 불러올 때는 저장된 정수 초를 기준으로 복원하며 이전 실행의 절대 틱을 재사용하지 않습니다. 별도 타이머 조합 검사는 자동 검사이며 실제 장시간 플레이나 벽시계 성능 측정을 의미하지 않습니다.
- **소집 복구 저장 실패:** 복구 완료 기록을 저장하지 못했을 때 대기 거래가 메모리에서 사라지지 않도록 보존합니다. 확정 후 소비 복구·이동 실패 복구의 마지막 저장 실패, 재시도와 중복 소비 방지를 검사했습니다. 실제 강제 종료 시 디스크 저장 순서는 미검증입니다.
- **이탈한 공격자 식별:** 이미 나간 헌터의 네이티브 이름을 읽을 수 없는 경우 캐시된 참가자 신원을 사용하고, 사망 후 낡은 공격 기록을 정리합니다. 투사체 주인과 아군 피해 차단, 비참가자 오인 방지, 실제 `main.js` 이벤트 연결을 자동 검사했습니다. 여러 PC의 이탈 직전 투사체 명중은 미검증입니다.
- **투척 제작·재접속:** 네이티브 목록이 일반 배열처럼 순회되지 않는 경우, 같은 엔티티가 반복 보고되는 경우, 마지막 재료 소비 후 저장 실패, 추적기 실물 삽입 후 지급 기록 저장 실패를 추가 검사했습니다. 부분 수량 저장 후 다른 헌터가 이어 만드는 동작과 직접 제작·40분 자동 지급의 같은 시각 경쟁도 검사했습니다.

기존 자동 검사에는 20분 공개·40분 자동 지급, 러너 출발부터 계산되는 경기 시계, 27종 중 일반 7종·어려운 2종의 중복 없는 제작법, 잘못된 투척 보존, 인벤토리 부족 시 지급 보류가 포함됩니다. 90·60·40·10블록 경고, 야생 부활 2회와 추가 부활, 소집의 같은 차원·350블록 경계·안전 지점·횟수 제한, 시작·종료·설정·전적·재접속·수신기 등 기존 기능의 모의 회귀 검사도 유지합니다. 자동 검사 통과는 실제 게임의 모든 경로를 확인했다는 뜻이 아닙니다.

### v1.5.0에서 이미 확인한 범위

아래는 [보존한 v1.5.0 보고서](history/QA_REPORT_v1.5.0.md)의 실기 기록을 이어받은 것입니다. v1.5.1 최종 패키지에서 전부 다시 실행한 결과로 표시하지 않습니다.

- 실제 Q키 투척으로 수량 0/2→1/2→단계 완료와 9단계 공동 제작 로직의 1인 경로, 이전부터 바닥에 있던 아이템 보존, 추적기 1개 지급을 확인했습니다. 여러 헌터가 동시에 참여한 시험은 아니었습니다.
- 당시 텍스처로 손·핫바의 상대 방향 바늘, 부활 아이템 사용 시 1개 소비와 기회 2→3을 확인했습니다. 이번 v1.5.1 원본 텍스처의 전체 픽셀 비교와 고정 목표 시각 시험은 위에 별도로 기록했습니다.
- 도우미 없는 v1.5.0 `.mcworld` 가져오기, BP/RP 파일 일치, 로비·메뉴·기존 5개 설정 카테고리·새 추적 상세 화면, 기본 20/40분 표시를 확인했습니다.
- 1인 연습의 5초 카운트다운, 야생 출발, 60초 유예 및 종료 시 임시 버프 해제, 체력 두 줄, 기본 야생 부활 2회, 앱 종료 후 일시정지 복원을 확인했습니다.

### 최종 배포 월드 가져오기 확인

시험 도우미가 없는 `Manhunt_Night_v1.5.1.mcworld`를 Minecraft UI에서 새로 가져왔습니다. 로비 생성·관리 메뉴·1인 연습 시작·카운트다운 후 야생 출발과 60초 도주 유예, 유예 종료 후 재생·느린 낙하 임시 효과 해제와 체력 두 줄·야생 부활 2회 유지까지 확인했습니다. 가져온 BP 52개·RP 41개 파일은 현재 소스와 바이트 단위로 일치했습니다. 카운트다운의 100틱 정확도는 자동 검사 결과이며 화면 관찰만으로 밀리초 정확도를 측정했다고 주장하지 않습니다. 시험한 가져오기 사본과 배포 원본 파일은 분리됩니다.

## 4. 기술적 제한과 남은 검증

**나침반 외형과 회전 방식은 구분합니다.** v1.5.1 이미지는 원본 나침반 셀과 동일하지만 정식 Script API에서 바닐라 나침반의 목표를 직접 변경하는 방식은 아닙니다. 헌터별 상대 방위를 32개 프레임에 대응하므로 수학적 최대 양자화 오차는 5.625도입니다. 실제 고정 목표 비교에서 손·핫바·인벤토리의 같은 외형과 왼쪽 방향을 확인했으나 바닐라의 흔들림·관성까지 동일하지 않습니다. 원본 출처·저작권·배포 조건과 라이선스 제외 범위는 [RP/NOTICE.md](../RP/NOTICE.md)에 기록했습니다. 프로젝트에 대한 Mojang의 별도 승인을 받았다는 의미는 아닙니다.

**아이템 소비와 월드 저장은 디스크까지 원자적으로 확정되지 않습니다.** 투척 제작·부활·소집은 준비 기록과 아이템 표식을 사용하며 결과가 불명확하면 거래를 중단해 관리자 확인을 요구합니다. 사라진 엔티티를 소비 완료로 추정하거나 자동 환불·재지급하지 않습니다. 모의 저장 실패 검사를 통과했더라도 정전·프로세스 강제 종료 시 엔진 저장 순서까지 보장하지 않습니다.

**소집 위치 검사는 보수적입니다.** 알려진 안전한 바닥·발과 머리 공간·주변 위험을 검사하므로 실제로 서 있을 수 있는 특수 블록도 제외될 수 있습니다. 전원의 안전 배치가 불가능하면 취소하고 소집서를 보존합니다. 복구가 남아 있으면 다음 소집과 초기화를 막습니다. 원위치 청크를 읽지 못할 때 관리자 메뉴에서 재시도하거나, 일시정지·전원 생존·안전 위치 확인 후 현재 위치 유지로 실패 거래를 정리할 수 있습니다. 불명확한 아이템을 자동 생성하지 않습니다.

**소집서 획득 OFF는 등록된 작업대 제작법 자체를 실시간 제거하지 못합니다.** 사용은 막지만 정적 제작법은 남습니다. OFF 상태에서 제작하면 이미 작업대에서 사용한 재료는 자동 반환되지 않습니다.

**요새 안내·도착 판정은 제공 월드의 기반 시드에 한정됩니다.** `FORTRESSES`와 요새 영역 데이터는 고정값이며 다른 시드 자동 탐색은 지원하지 않습니다. 다른 월드에 애드온을 적용할 때는 요새 힌트를 OFF로 설정해야 합니다. 후보 재료의 획득 방법·난도와 API 근거는 [API_RESEARCH_v1.5.md](API_RESEARCH_v1.5.md)에 기록했습니다. 모든 시드에서 20분 안에 어려운 재료 6개씩을 확보할 수 있다는 보장은 없습니다.

남은 실기 검증은 [친구들과 확인하기](FRIENDS_TEST.md)에 정리했습니다. 이 문서는 **실행 계획**이며 아직 통과 결과가 아닙니다.

- 실제 26.62 클라이언트, 3~4인 친구 초대·리소스 팩 수신·동시 투척·미접속 지급·헌터 처치·4단계 경고·여러 헌터 소집·수신기 카메라: 미검증.
- v1.5.1 최종 패키지는 실제 가져오기·로비·1인 시작 흐름을 확인했습니다. 전체 실기 회귀는 미완료입니다. 격리 QA 사본의 오버월드 경계 복귀와 수신기 광선 생성·해제도 별도로 확인했습니다.
- 기본 20/40분 실제 장시간 플레이, 일반 드래곤 전투, 강제 종료/정전, 엔진의 디스크 저장 순서: 미검증.
- FPS/TPS·메모리·네트워크 실측 및 전후 비교: 미실시. 처리 생략·캐시·변화 시 저장을 적용했어도 성능 개선 수치로 표현하지 않습니다.
- 원본 월드의 과거 실험 사용 이력은 보존했습니다. 활성 실험 옵션을 끈 출력에서도 실험 이력 경고가 표시될 수 있습니다. 스크립트는 안정 API를 사용합니다.

### 팩 경고와 셰이더 분리 시험

26.63에서 빨간 “하나 이상의 리소스 팩 또는 행동 팩을 불러오지 못했습니다” 메시지가 표시됐습니다. Manhunt BP/RP의 게임 내 기술 정보는 모두 “오류가 발견되지 않았습니다”였고, 검사한 콘텐츠 로그에 팩·스크립트 오류는 없었습니다. 신규 명령어의 바닐라 `recipe` 별칭 충돌은 `/mh:trackerrecipe`로 변경했습니다. 이 충돌을 없앤 시험 사본에서도 빨간 메시지는 남았습니다.

사용자 요청에 따라 설치된 셰이더 3종(BSLB Dreamy, Prizma, Solar)을 별도 백업 폴더로 옮기고 해당 글로벌 활성 항목을 해제했습니다. 앱을 완전히 재시작해도 경고가 남았습니다. 이어 게임 UI에서 **새 바닐라 월드**를 만들고 활성 리소스 팩 없음·활성 행동 팩 없음·기본 글로벌 텍스처만 사용 중임을 확인했으며, 이 월드의 채팅에서도 같은 빨간 메시지를 직접 재현했습니다. 따라서 이 메시지만으로 Manhunt 또는 셰이더의 로딩 실패라고 판단하지 않습니다.

공식 [MCPE-241656](https://bugs.mojang.com/browse/MCPE-241656)에도 팩 없는 월드에서 같은 경고가 나타나는 증상이 Confirmed/Open으로 기록돼 있습니다(2026-11-08 확인). 공식 영향 버전 목록에는 26.63이 없으므로 현재 PC의 내부 원인까지 확정한 것은 아닙니다. 경고는 여전히 표시되며 숨기거나 해결했다고 주장하지 않습니다. 셰이더 백업 및 다른 기존 월드는 배포 소스에 포함하지 않았습니다.

## 5. 배포 판정

**Pre-release**로 배포합니다. 정적·자동 검사, ZIP·`.mcworld`·`.mcaddon`·해시 검사와 단일 클라이언트의 위에 명시한 범위를 확인했습니다. 3~4인 실전 검증 전에는 Stable로 표시하지 않습니다. GitHub PR·Actions·병합·릴리스 상태는 저장소의 실제 기록과 최종 완료 보고에서 별도로 확인합니다.
