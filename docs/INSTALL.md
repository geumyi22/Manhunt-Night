# Manhunt Night v1.7.5 — 설치 및 업데이트 (Pre-release)

**출발 좌표 수정 RC1:** 동일한 v1.7.5를 이전에도 설치했다면 반드시 월드 복사본에서 구버전 행동 팩을 비활성화/제거하고 최신 빌드를 다시 가져오세요. 기존 팩 UUID/버전 번호를 유지하기 때문에 게임이 예전 팩을 캐시할 수 있습니다. `/mh:menu`에서 **`시험 빌드: 지면 출발 수정 RC1`**이 보이는지 확인하면 실제로 최신 코드가 활성화됐는지 구분할 수 있습니다. 이전 월드·전적·저장 데이터는 백업 후 유지하세요.

**공식 Stable은 v1.6.0입니다.** 이 버전은 다양한 맵과 요새 자동 발견을 개선한 시험 버전이므로 실제 플레이 월드에 바로 덮어쓰지 마세요.

## 기존/새 월드 설치

1. 기존 세계는 Minecraft에서 **복사본**을 만들고, 가능하면 `.mcworld`로 별도 백업합니다.
2. [v1.7.5 GitHub Actions](https://github.com/geumyi22/Manhunt-Night/actions)의 성공한 빌드 아티팩트에서 `.mcaddon` 또는 `.mcworld`을 받습니다.
3. **다른 맵:** `.mcaddon`을 가져와 복사본의 Behavior Pack·Resource Pack을 활성화합니다. 이미 포함된 `.mcworld`에 `.mcaddon`을 중복 적용하지 마세요. 기존 맨헌트 팩도 동시에 사용하지 마세요.
4. 오버월드에 첫 입장하면 주변의 빈 공간에 파란/빨간 **21×21 공중 로비**가 자동 생성됩니다. 겹치는 블록이 있으면 안전한 다른 위치를 찾습니다. 실패 시 빈 곳에서 호스트가 `/mh:lobbycreate`로 재시도합니다. `/mh:unstuck`은 이미 만들어진 로비로 이동합니다.
5. `/mh:menu`에서 러너·헌터·게임 설정을 정하고 시작합니다. 5초 카운트다운과 기본 60초 도주 유예는 유지됩니다.

**데이터 보호:** 새로운 팩을 가져오기만 해도 월드가 자동 백업되는 것은 아닙니다. 로비 건설은 게임 세계의 빈 공간에 블록을 놓으므로 월드가 변경됩니다. 사전 블록 점유 검사와 실패 시 롤백을 시도하지만, 엔진 종료/청크 오류를 포함한 모든 경우의 무손실을 보장할 수는 없습니다. 게임 시작·로비 초기화는 참가자 인벤토리·장비·경험치를 지웁니다. 기존 게임의 지형·상자·드래곤은 경기 초기화로 복원되지 않습니다.

## 다른 맵의 네더 요새

- **자동 발견 ON(기본):** 네더 탐험 중 자연 발생 위더 스켈레톤과 주변 네더 벽돌이 함께 확인되면 해당 위치를 최대 8곳까지 자동 기록합니다. 자연 스폰 이벤트가 없거나 충분한 증거를 확보하지 못하면 기록되지 않습니다.
- **러너 전용 힌트:** 40분 경과 또는 헌터 선진입 시, 탐험해 기록한 추정 좌표가 있으면 러너에게만 전달합니다. 없으면 미발견 안내만 표시합니다.
- **수동 대안:** 호스트가 네더에서 `/locate structure fortress`로 확인한 X/Z를 `/mh:menu → 다른 맵 / 네더 요새 좌표 관리`에 입력할 수 있습니다. 수동 등록 좌표가 자동 후보보다 우선합니다.
- **기능 OFF:** 특수 맵에서 요새가 없거나 탐색을 원하지 않으면 `④ 월드 / 안내 / 보상`에서 요새 힌트나 자동 발견을 끌 수 있습니다. 추적·부활·승패에는 영향이 없습니다.
- **좌표의 의미:** 자동 좌표는 발생 몹 근처의 탐지 위치로, 구조물 중심/최단 경로/미탐험 영역의 정확한 생성 위치를 뜻하지 않습니다.

월드 경계는 원본 시드 이외의 맵에서 시작점 기준 오버월드 10,000×10,000·네더 1,250×1,250이며 엔드는 원점 기준입니다. 특수 맵은 경계 기능을 OFF로 할 수 있습니다.

## 호환성 및 QA

- Script API `@minecraft/server` 2.11.0 / `@minecraft/server-ui` 2.3.0 사용, 별도의 Beta APIs 실험 설정을 요구하지 않습니다.
- 자동 테스트·빌드 결과: [GitHub Actions](https://github.com/geumyi22/Manhunt-Night/actions). 실제 기기 검증 상태: [QA 보고서](QA_REPORT.md).
- *v1.6.0 Stable과 다른 시드의 실제 QA를 동일한 것으로 취급하지 않습니다.* 구버전의 월드·소스·릴리스 기록은 변경하지 않습니다.
