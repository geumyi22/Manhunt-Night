# v1.7.0 외부 맵 적용 — Pre-release

1. **반드시** 대상 월드를 복제하고 원본은 보존합니다. 새 게임/로비 초기화는 참가자의 인벤토리·장비·경험치를 삭제하며, 기존 건물이나 드래곤을 복원하지 않습니다.
2. v1.7.0 작업 브랜치의 [GitHub Actions](https://github.com/geumyi22/Manhunt-Night/actions)에서 성공한 전체 빌드 아티팩트를 받습니다. 다른 월드에는 해당 .mcaddon의 행동/리소스 팩을 적용하고, 원본 전용 .mcworld는 기존 지형을 사용하는 데에만 씁니다.
3. 다른 맵에 최초 적용할 때는 **오버월드에서** 접속합니다. 맨헌트는 첫 입장 위치 근처의 비어 있는 공간(Y=304 우선)에 **기존과 동일한 파란색·빨간색 공중 로비**를 자동 건설하고 그곳으로 이동시킵니다. 주변에 블록이 있으면 다른 좌표·높이를 검사하며, 안전한 공간이 없으면 기존 블록을 건드리지 않고 중단합니다. 글로벌 월드 스폰은 다른 시드에서 변경하지 않습니다.
4. 네더에서 /locate structure fortress 명령으로 실제 X/Z 좌표를 확인한 후 호스트가 /mh:menu → 다른 맵 / 네더 요새 좌표 관리에서 등록합니다. 좌표가 없다면 잘못된 힌트 대신 미등록 안내를 표시합니다.
5. 오버월드/네더 경계는 시작 위치를 중심으로 설정됩니다. 제작 맵에서 특별한 이동 경로가 필요하면 ④ 월드 설정에서 경계를 OFF로 전환하세요.
6. 로비가 생성되지 않으면 오버월드의 열린 곳으로 이동하여 `/mh:lobbycreate`를 사용해 다시 시도합니다. `/mh:unstuck`은 이미 생성된 로비로 이동하는 명령어입니다. 경기 시작 시 참가자 인벤토리는 맨헌트 규칙에 따라 초기화됩니다.
7. 로비 메뉴·추적기·부활·소집·차원 이동·승패를 게임 복사본에서 실제로 시험합니다. 서로 충돌하는 다른 맨헌트 애드온을 동시에 활성화하지 마세요.

**호환성 제약:** 새로운 맵의 네더 요새를 자동으로 식별하거나 모든 커스텀 차원·다른 팩을 지원한다고 보장하지 않습니다. 등록 좌표 근처 ±192블록의 복수 네더 벽돌이 도착 판정 근거이므로 실제 요새 좌표를 등록해야 합니다. 원본과 동일한 시드를 재사용한 개조 맵은 예외일 수 있습니다.

**검증 상태:** 코드/자동화 결과는 [QA](QA_REPORT.md)에서 확인합니다. 실기기 미검증 항목은 완료 처리하지 않습니다.

# v1.6.0 설치 및 업데이트

Stable 전체 파일은 [Manhunt_Night_v1.6.0_Stable_FullFiles.zip](https://github.com/geumyi22/Manhunt-Night/releases/download/v1.6.0/Manhunt_Night_v1.6.0_Stable_FullFiles.zip)에서 받습니다. 기존 v1.6.0 게임 파일은 동일하며, Stable 묶음에는 최신 소스·문서·QA·해시를 추가합니다. 이전 배포 파일과 원본 월드는 보존합니다.

1. 기존 월드와 팩은 보존하고 중요한 월드는 내보내기로 백업합니다.
2. `Manhunt_Night_v1.6.0.mcworld`를 열어 Minecraft에 가져옵니다. Behavior Pack과 Resource Pack이 이미 포함되어 있어 이 파일 하나로 동작합니다.
3. 새 월드 이름에서 v1.6.0을 확인하고 친구를 초대하여 총 2~8명이 접속합니다. `/mh:menu`로 설정·러너 선택·시작. 친구에게 필요한 리소스 팩을 받도록 안내합니다.
4. 다른 월드에서는 먼저 복사본을 만들고 `.mcaddon`을 가져온 뒤 행동 팩과 연결 리소스 팩을 활성화합니다. 다른 맨헌트 팩과 함께 사용하지 마세요. 새 mcworld에는 mcaddon 중복 적용이 필요 없습니다.

기준 게임 26.62, 공식 안정 Script API server 2.11.0 / server-ui 2.3.0. 실험 API는 사용하지 않습니다. 호스트와 친구는 동일한 게임 버전으로 접속합니다. 실제 QA 기기 버전은 QA 보고서에 별도로 기록합니다.

## 다른 시드 월드의 요새 힌트

네더 요새 좌표와 도착 판정 영역은 제공 `.mcworld`의 기반 시드에 맞춰 고정되어 있습니다. 임의의 월드에서 요새를 자동으로 찾는 기능은 없습니다. **다른 시드의 월드에 `.mcaddon`을 적용할 때는 경기 시작 전에 관리자 → 게임 설정 → ④ 월드·안내·보상에서 요새 힌트를 OFF로 설정하세요.** 켜 두면 해당 월드에 없는 좌표를 안내하거나 도착 여부를 잘못 판정할 수 있습니다. 추적기·부활 등 다른 기능은 이 설정과 독립적으로 사용할 수 있습니다.

2인부터 정식 경기를 시작할 수 있습니다. 8명은 게임 규칙 상한이며 호스트/서버의 접속 정원과 실제 성능을 자동으로 늘리지는 않습니다.

## 기존 설정 이관

기존 저장 상태/전적 형식은 유지합니다. v1.4 설정은 기존 나침반/HUD 모드 및 부활 3회를 보존합니다. 신규 월드는 무작위 제작 20/40분·기본 부활 2회입니다. 기존 월드에서도 관리 메뉴의 추적 상세와 러너 상세에서 신규 규칙을 선택할 수 있습니다. 저장된 경기 재개 시 제작법/지급 기록/남은 부활을 유지합니다.

## 파일 무결성

`SHA256SUMS.txt`는 개별 파일의 SHA-256입니다. 전체 ZIP의 SHA-256은 같은 이름의 `.zip.sha256` 파일에 있습니다. Windows PowerShell `Get-FileHash -Algorithm SHA256 -LiteralPath <파일>` 결과와 비교합니다.

## 테스트 권장

새 환경에 적용할 때는 복사 월드에서 메뉴·참가자 접속을 먼저 확인하세요. 실제 2·3인 게임 흐름과 친구들의 직접 QA 결과는 [QA 보고서](QA_REPORT.md)에 있습니다. 실제 8인 규모와 FPS·게임별 네트워크 수치는 확인되지 않았으며, 기존에 확인한 시험을 반복할 필요는 없습니다. 새 라운드를 시작해도 채굴·건축·드래곤은 복구되지 않습니다.

원본 지형의 과거 실험 사용 이력을 보존하므로 최초 입장에 실험적 세계 경고가 나올 수 있습니다. 이번 팩은 안정 API를 사용하며 활성 실험 옵션은 꺼져 있습니다.

26.63 QA에서는 빨간 팩 로딩 경고가 **팩을 전혀 적용하지 않은 새 바닐라 월드에도** 나타났습니다. Manhunt의 팩 기술 정보는 오류 없음이었고 확인한 게임 기능은 실행됐습니다. 같은 증상의 공식 기록 [MCPE-241656](https://bugs.mojang.com/browse/MCPE-241656) 및 분리 시험 결과는 QA 보고서에 있습니다. 경고가 보이면 실제 팩 기술 정보·콘텐츠 로그와 기능 실행 여부를 함께 확인하세요. 이 메시지 자체를 해결했다고 보고하지 않습니다.
