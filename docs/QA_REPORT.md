# Manhunt Night v1.6.0 — QA 보고서

상태: **Stable 배포 승인 (2026-11-14). 정식 경기 2~8명(러너 1명·헌터 1~7명), 1인 연습 유지.**

사용자와 친구들의 직접 QA, 실제 2·3인 검증, 212개 회귀·타입·패키지 검사 및 CI를 반영했습니다. 사용자는 아래 확인 범위와 제한을 안내받은 뒤 Stable 출시를 요청했습니다. 기존 v1.6.0 게임 코드는 그대로이며, 최신 소스·문서·이 보고서는 별도 Stable 묶음으로 제공합니다. 기존 태그·릴리스 자산과 해시가 있는 과거 QA 자료는 보존합니다. 실제 게시 및 최종 다운로드 해시 결과는 [릴리스](https://github.com/geumyi22/Manhunt-Night/releases/tag/v1.6.0)와 [Issue #3](https://github.com/geumyi22/Manhunt-Night/issues/3)에 기록합니다.

## 사용자 직접 QA 반영

사용자는 이전 대화에서 **“남은 미검증 2개 검증완료”**라고 보고했고, 친구들과 직접 플레이하며 QA를 했다고 다시 확인했습니다. 이 보고와 각 시험에 대한 “됨”, “잘됨”, “성공” 응답을 수동 실기 근거로 인정합니다. 영상이나 자동 로그가 없다는 이유로 확인된 플레이 항목을 다시 미검증으로 돌리거나 같은 시험을 반복 요구하지 않습니다.

실제 2·3인 시작·재접속, 공동 제작·헌터별 추적기, 소집 성공·팀 대기·횟수 제한, 같은 차원 수신기 카메라·광선, 부활·토템·승패의 확인 결과는 아래에 보존합니다. 직접 확인한 게임 동작과 별도로 측정한 성능 수치를 구분합니다.

## 변경과 보존

- 시작 인원 검사와 메뉴·새 월드 이름만 2~8명으로 확장합니다. 8명은 규칙상 상한이며 성능 보장값이 아닙니다.
- 기존 팩 UUID·저장 스키마·설정·제작 재료·20/40분 규칙·부활·소집 규칙은 유지합니다. 기존 월드 DB를 읽기 전용 기반으로 사용합니다.
- 2인에서는 소집할 다른 헌터가 없으므로 아이템을 소비하지 않습니다. 공동 제작은 한 헌터가 진행합니다.
- 기존 [v1.5.1 QA](history/QA_REPORT_v1.5.1.md), [재검증](QA_REVALIDATION_2026-11-14.md), [후속 실측](QA_RUNTIME_v1.5.1_2026-11-14.md)을 보존합니다. 과거 실측을 이번 변경의 통과 결과로 재분류하지 않습니다.

## 자동·패키지 검증

검증일: **2026-11-14 KST**. 기존 204개 회귀 검사를 유지하고 8개를 추가하여 **212/212 통과**, 실패·건너뜀 0개입니다. 기존 시작 인원 기대치는 새 2~8명 규칙에 맞게 조정했습니다. 추가 검사는 모의 Bedrock 환경에서 2인 승패·전적·재접속, 1인 연습, 9인 거절 시 상태 보존, 8인 헌터별 지급·추적, 소집 안전 배치와 실패 시 미소비를 확인합니다. 실제 8인 접속 시험은 아닙니다.

- 공식 `@minecraft/server` 2.11.0 / `@minecraft/server-ui` 2.3.0 기준 타입 검사 통과.
- JavaScript 구문 22개 파일 통과. JSON 43개, 아이템 36개, 추적기 32프레임·28종 원본 이미지, 제작법·재료·UUID·안정 API 의존성 검사 통과.
- 전체 월드·애드온·소스·문서 ZIP 빌드, 내장 BP/RP 일치, ZIP CRC 및 SHA-256 검사 수행. 최종 생성물의 `PACKAGE_CHECKS.json`, `BUILD_MANIFEST.json`, `SHA256SUMS.txt` 및 전체 ZIP 외부 `.sha256`을 함께 제공합니다.
- 기반 v1.5.1 `.mcworld`는 읽기 전용으로 사용합니다. DB 4개 파일의 바이트 동일성과 빌드 입력 무변경을 검사합니다. 측정 코드는 배포 BP/RP에서 금지합니다.

실행 로그: [자동 212개](qa/2026-11-14-v160/tests.txt), [타입](qa/2026-11-14-v160/types.txt), [구문](qa/2026-11-14-v160/syntax.txt), [소스 검사](qa/2026-11-14-v160/source-checks.json). ## 앞선 단기 시험의 성능 실측과 한계

호스트 i5-13600KF·RTX 3070·RAM 약 32 GiB 환경이며 기존 BSLB Dreamy·영상 설정을 유지했습니다. 렌더 거리 설정값 384, VSync ON, MSAA 16, FOV 90. 배경 작업과 셰이더를 통제한 비교 벤치마크가 아니며 관찰 코드 자체의 비용도 분리하지 않았습니다.

- TPS는 엔진의 실제 경과 틱 / 벽시계 경과 시간입니다. FPS가 아닙니다. 최종 정상 JSON 169개, 최초 샘플은 구간 집계에서 제외했습니다.
- 공식 경기 시작부터 첫 종료 관측까지 **680.941초, 시간가중 19.679 TPS**입니다. 이탈·일시정지·재접속 전환을 포함합니다.
- 상태가 같은 2인 유예/진행 구간 합계 **615.049초, 19.998 TPS**. 전환 구간을 제외한 값만으로 전체 경기를 설명하지 않습니다.
- 이탈·일시정지 전환에서 **100틱에 15.817초, 최저 6.322 TPS**가 관찰됐습니다. 원인은 미확정이며 게임 코드 결함이나 성능 개선으로 단정하지 않습니다.
- 호스트 프로세스 메모리 178샘플 / 180.839초: Working Set 중앙 **2849.05 MiB**, 최대 **2893.59 MiB**; Private Bytes 중앙 **4588.81 MiB**, 최대 **4860.65 MiB**. 전체 CPU 용량 기준 시간가중 **26.32%**. 이 시간창에는 1/2명 접속과 카운트다운·유예·진행·일시정지가 섞여 있어 순수한 2인 진행 메모리로 표시하지 않습니다.
- **FPS·게임 네트워크 미측정.** 앞선 v1.5.1 시도에서 PresentMon이 종료 코드 1과 CSV 미생성으로 실패했으며, 그 시도를 v1.6.0 FPS 검증으로 세지 않습니다. 다른 PC의 FPS·메모리도 미측정입니다.

숫자 원본과 계산식·구간·제외 기준은 [summary.json](qa/2026-11-14-v160/runtime/summary.json), [틱 표본](qa/2026-11-14-v160/runtime/tps-samples.jsonl)에 있습니다. 약 11분의 경기 관측과 약 3분의 메모리 창으로 장시간 안정성이나 8인 성능을 보장하지 않습니다.

기존 환경에서 보이던 빨간 팩 경고는 해결 완료로 처리하지 않았습니다. 이전 v1.5.1의 바닐라 분리 시험·Lighting 오류 기록은 [과거 QA](history/QA_REPORT_v1.5.1.md)와 [후속 실행 기록](QA_RUNTIME_v1.5.1_2026-11-14.md)에 보존합니다.

## 후속 LONG 시험 — 기본20/40분과 지급 전후 재실행

- 기본20분 공개는 경기1197→1202초, 미완성 재료2/8을 남긴 기본40분 자동지급은2399→2404초의 연속 표본에서 관찰했습니다. 헌터 추적기0→1·러너0개, `completion=auto`·지급1회를 확인했습니다. 약5초 간격의 관측이며 정확20:00/40:00 호출시각 계측은 아닙니다.
