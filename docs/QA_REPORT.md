# Manhunt Night v1.7.5 — 다른 맵 및 네더 요새 자동 발견 QA

**배포 판정: Pre-release 개발 후보 (2026-11-18).** 이전 [v1.6.0 Stable QA 원문](history/QA_REPORT_v1.6.0.md), [v1.6.0 공식 릴리스](https://github.com/geumyi22/Manhunt-Night/releases/tag/v1.6.0), 월드·배포 파일·기존 저장 데이터는 변경하지 않았습니다. 새로운 v1.7.5에서 실제 Minecraft 외부 월드 E2E를 통과했다고 주장하지 않습니다.

## 1. 변경 내용

- 기존 맨헌트와 동일한 21×21 공중 로비를 **다른 시드에서도 자동 생성**. 빈 공간·주변 위치·여러 높이를 확인하고, 장애물이 있으면 기존 블록을 덮어쓰지 않습니다.
- 블록 건설 실패 시 이미 배치한 블록만 최대한 되돌리고 자신이 만든 ticking area 정리. 이미 생성된 로비 재사용·이전 좌표형 로비에서 건축형으로 전환.
- 다른 시드의 오버월드·네더 상대 경계, 네더 요새 수동 좌표 등록·오안내 방지 유지.
- **네더 요새 자동 발견:** 자연 발생 `minecraft:wither_skeleton`의 엔티티 스폰 이벤트(`cause=Spawned`)와 주변 7×7×3 공간의 요새 벽돌 ≥8개, 같은 차원 참가자가 96블록 이내에 있는 조건을 모두 만족할 때만 X/Z 기록.
- 자동 기록은 중복 96블록 이내 후보를 걸러 **최대 8곳** 저장하며, 단일 월드 상태 JSON에 보존해 재접속·다음 라운드에서도 활용.
- 40분/헌터 선진입 이전에는 자동 후보를 알리지 않으며, 조건 충족 시에만 **러너에게 한 번** 안내. 미발견 시 잘못된 원본 시드 좌표를 출력하지 않고, 호스트 수동 좌표가 자동보다 우선.
- 별도 `fortressAuto` ON/OFF 옵션. 기존 추적기·부활·소집·수신기·승패·기본 20/40분 제작 정책과 저장 스키마 1 호환 유지.

이 테스트들은 스크립트를 *모의 Bedrock 이벤트·인벤토리·블록 구조*에 연결한 정적/회귀 검사 및 배포 무결성 검사이며, 실제 게임의 모든 시드·조건에서 탐지됐다는 결과가 아닙니다.

## 3. 미검증 및 기술적 제약

- [ ] 실제 다른 시드 월드 첫 입장 후 공중 로비 외형·지형 보호·건축 실패 복구 확인
- [ ] 실제 2~3인 또는 그 이상 게임 재접속·소집·추적·네더/엔드 이동·승패 검증
- [ ] 실제 네더 요새에서 자연 위더 스켈레톤 출현 시 자동 기록과 좌표 공개 확인
- [ ] 실제 40분·헌터 선진입에서 러너 전용 힌트 및 재접속 후 자동 기록 유지
- [ ] 성능 및 다른 애드온 충돌 시험

정식 `CommandResult`는 `/locate`의 X/Z를 반환하지 않습니다. `Dimension.getGeneratedStructures`는 아직 Pre-release API이며 **주변 지정 좌표의 구조물 존재만 확인**하지 미탐험 요새를 검색하지 않습니다. 본 구현은 정식 API만 사용하며 자연 스폰·네더 벽돌을 결합한 **근거 있는 위치 추정**입니다. 자연 스폰 이벤트가 없거나 탐지 대상이 너무 멀면 발견되지 않으며, 타 애드온·자연스럽지 않은 스폰·사용자 건축물에서는 오인/실패 가능성이 있습니다.

작업 시점의 연결된 테스트 PC에서 신규 v1.7.5 실제 게임 실행을 확인하지 못했습니다. 이 한계가 남아 있어 **v1.7.5 Stable 승격은 보류**하고, [Issue #12](https://github.com/geumyi22/Manhunt-Night/issues/12)에 실기 검증 항목을 남깁니다.

## 4. 이전 Stable과의 관계

- 이전 v1.6.0의 2·3인 실기 결과는 해당 버전의 검증으로 그대로 인정합니다.
- v1.7.5 자동 테스트 결과를 다른 시드의 실기 E2E로 대신 표시하지 않습니다.
- 기존 v1.6.0 릴리스 태그/자산/해시를 변경하지 않고, v1.7.5는 별도 개발 브랜치·Draft PR로 관리합니다.
