# Manhunt Night v1.5.0 개발 기록

기록일: 2026-11-08 KST. **자동·정적 검사와 일부 실제 클라이언트 검증을 완료한 Pre-release 후보**입니다. 실제 3~4인 친구 초대 검증을 완료한 Stable 버전으로 취급하지 않습니다.

이전 대화의 완료 표현 대신 실제 저장소 코드와 v1.4.0 검사 자료를 기준으로 변경했습니다. 저장소에 v1.4.0 완성 월드 바이너리가 없어 사용자가 제공한 원본 월드를 **복사**하고 v1.5.0 Behavior Pack과 Resource Pack을 넣는 방식으로 배포 월드를 구성했습니다. 기존 입력 파일과 배포본을 덮어쓰지 않았으며, 출력 월드의 원본 DB 4개 파일이 바이트 단위로 유지되는지 확인했습니다. 이전 설치·변경·QA 문서는 `docs/history`에 보존했습니다.

공동 기획자의 손그림 실파일은 이번 작업에 전달되지 않았습니다. 따라서 나침반·동심원·토템 조합·종이에 대한 사용자 요청의 문자 묘사를 디자인 참고로 사용했습니다. 그림 자체를 확인하거나 그대로 적용했다고 주장하지 않습니다.

## 구현과 규칙 통합

### 추적기와 팀 제작

- 이름은 `§a§l러너 추적기§r`입니다. 기존 8방향 표시를 플레이어별 상대 방위에 따른 32프레임으로 확장하고, 검토 과정에서 발견한 좌우 반전도 수정했습니다. 소유자별 회전 상태를 분리하며 손·핫바·인벤토리의 소지 아이템을 갱신합니다.
- 같은 차원에서는 러너를 추적하고, 다른 차원에서는 러너의 차원과 해당 차원의 마지막 확인 위치를 구분합니다. 차원 간 좌표를 임의 환산해 현재 위치처럼 표시하지 않습니다.
- 신규 월드 기본 방식은 무작위 투척 제작입니다. 20분까지 비공개·제작 불가, 20분 공개, 40분까지 팀 미완성일 때 자동 지급합니다. 러너 출발부터 시간을 계산하여 도주 유예를 포함하고, 5초 카운트다운·일시정지·종료 이후 시간은 제외합니다.
- 오버월드 후보 27종에서 일반 7종과 어려운 재료 2종을 중복 없이 뽑아 9단계 순서를 고정합니다. 어려운 재료는 기본 각각 6개이며 설정으로 변경할 수 있습니다. 재료별 수급·난도는 [API 연구 문서](API_RESEARCH_v1.5.md)에 기록했습니다.
- 헌터가 명시적으로 제작 모드를 켠 경우에만 출처가 확인된 새 투척을 처리합니다. 팀이 순서·부분 수량 진행도를 공유하고, 완료한 팀의 각 헌터에게 한 번씩 지급합니다. 오프라인·인벤토리 부족은 보류하며 분실·사망만으로 재지급하지 않습니다.
- 기존 나침반 제작·자동 HUD 모드는 설정으로 유지하되 신규 방식과 동시에 실행되지 않도록 통합했습니다. 기존 설정 마이그레이션은 이전 추적 방식과 기본 부활 3회 설정을 보존하고, 신규 월드에는 새 기본값을 적용합니다.

### 러너 경고와 부활

- 기존 5블록 경고를 **90·60·40·10블록**으로 통합했습니다. 같은 차원의 가장 가까운 살아 있는 참가 헌터와의 3차원 거리를 사용하며 러너에게만 알립니다. 구간 상태·알림 간격을 분리하고 경계 흔들림을 완화합니다.
- 신규 월드의 야생 부활은 기본 2회입니다. 참가 헌터의 직접 공격 또는 귀속 가능한 투사체 처치는 즉시 패배로 처리하고, 비참가자·자기 자신을 참가 헌터로 분류하지 않습니다.
- 부활 토템은 중앙 불사의 토템과 주변 네더라이트 주괴 8개로 제작합니다. 살아 있는 러너가 사용하면 기존 부활 상태에 기회 1회를 추가하고 아이템을 소비합니다. 기본 누적 부활 예산은 최대 3회이며, 사용한 기회 때문에 추가 아이템 상한이 다시 열리지 않습니다.
- 최대 체력 40HP, 기본 포만감 I, 유예 중 포만감 V·재생 I·느린 낙하 I를 유지합니다. 유예가 끝나면 임시 효과를 제거하고 부활 시 전체 체력을 채웁니다. 인벤토리 유지 설정도 보존했습니다.

### 헌터 소집과 설정

- 소집서는 경기 중 헌터가 사용하며, 사용자와 같은 차원의 헌터만 이동시킵니다. 다른 차원의 헌터에게는 정보만 전달합니다.
- 사용자와 목적지 모두 같은 차원 러너로부터 **350블록 초과**여야 합니다. 정확히 350블록도 금지합니다. 전원 목적지의 지면·공간·위험·월드 경계·서로 겹침을 검사하고 실제 이동 직전에 조건을 재검사합니다.
- 기본 시작 지급품으로 제공하지 않습니다. 획득 방식·기능·쿨다운·경기당 사용 횟수를 설정하며 성공 시 한 장을 소비합니다. 실패 시 원위치 복귀와 아이템 보존을 시도합니다.
- 기존 설정 5개 카테고리를 유지하고 추적 제작, 러너 상세, 소집 하위 페이지를 추가했습니다. 잘못된 시간 순서·거리 순서·부활 상한 입력은 설정 전체에 부분 적용되지 않도록 거부합니다.

## 거래·재접속·라운드 안전성

아이템 소비와 월드 상태 저장의 결과가 불명확할 때 성공으로 추정하지 않는 방향으로 설계했습니다.

- **투척 제작:** 준비 기록과 소비 진행을 저장합니다. 중복 이벤트·오래된 바닥 아이템·합쳐지거나 변한 수량·잘못된 출처는 재료로 확정하지 않습니다. 불확실한 소비·지급은 기록을 유지하고 관리자 확인으로 처리합니다.
- **부활 토템:** `revivePending`과 비중첩 아이템의 표식으로 준비·소비 시도·완료를 구분합니다. 동기 오류에는 원본 복사본으로 환불을 시도하며, 저장과 환불이 모두 실패하면 추가 사용·초기화를 차단합니다. 남은 표식으로 결과를 확인할 수 있으면 자동 복구합니다.
- **부활 수동 확인:** 호스트가 일시정지·종료·로비 상태에서 현재 토큰과 접속 중인 러너를 확인해야 합니다. 소비 완료 확인은 기회 1회만 적용하고, 취소 확인은 이전 기회로 되돌립니다. 어느 선택도 새 아이템을 자동 생성하지 않습니다. 중복 표식·다른 플레이어 소유 표식·남아 있는 아이템과 모순되는 소비 완료 확인은 거부합니다.
- **소집:** 부분 이동 실패를 기록하고 복귀가 끝날 때까지 추가 소집·초기화를 막습니다. 원위치 청크를 읽지 못하면 재시도하거나, 관리자 확인과 안전 조건을 충족한 경우 현재 위치를 유지하는 정리 절차를 사용합니다.
- **승패:** 사망·드래곤 사건을 `pendingOutcome`에 라운드와 함께 저장합니다. 처리 콜백 전에 재시작되어도 판정을 복구하며, 초기화·다음 라운드의 오래된 콜백은 무효화합니다. 같은 처리 구간의 러너 치명상은 드래곤 처치보다 우선합니다.

이 기록은 Minecraft의 아이템·엔티티·동적 속성 저장을 하나의 원자적 디스크 작업으로 만드는 기능이 아닙니다. 정전·프로세스 강제 종료까지 손실·복제를 완전히 방지했다고 보장하지 않습니다. 불명확한 결과를 자동 환불·추가 지급으로 덮지 않고 관리자에게 드러내는 것이 복구 원칙입니다.

## 보존한 기존 기능

3~4인 경기와 1인 연습, 러너 지정·무작위 선정, 시작 카운트다운·도주 유예, 헌터 무제한 부활, 사망·드래곤 승패, 헌터 간 위치 공유, 10000×10000 구역과 차원별 경계, 요새 안내, 수신기·카메라·광선, 엔드 보상, 로비·관리 메뉴, 메뉴 중복 방지, 시작 지급품 회수·복구, 기능별 ON/OFF, 누적 전적, 자동 일시정지, 재접속 처리와 기존 명령어를 회귀 검사에 포함했습니다. 명시적으로 바뀐 규칙 외에 기존 코드를 전면 재작성하지 않았습니다.

실제 26.63 클라이언트에서 다음을 관찰했습니다.

1. 격리한 검사 월드에서 실제 Q키 투척의 부분 수량과 9단계 완료, 추적기 1회 지급을 확인했습니다. 최초 네이티브 이벤트 목록 순회 오류를 수정한 뒤 다시 검사했습니다. 검사 도우미는 배포 팩에 포함하지 않습니다.
2. 추적기 `frame 24`에서 동쪽 목표가 남쪽을 보는 플레이어의 왼쪽에 표시되는 손·핫바 이미지를 확인했습니다.
3. 최종 일반 배포 월드의 가져오기, 로비, 설정, 1인 연습의 카운트다운과 60초 도주 유예를 확인했습니다.
4. 러너 최대 체력 40HP와 기본 부활 2회, 저널을 적용한 부활 토템 사용의 남은 기회 2→3 및 아이템 소비를 확인했습니다. 이후 `fall` 유형 100 피해로 야생 사망·부활을 유도하여 남은 기회 3→2와 전체 체력 회복을 확인했습니다.

이 목록은 실제 20분 서바이벌 수급, 모든 각도·차원, 전체 이벤트 순서 또는 여러 기기의 동시 플레이 검증을 의미하지 않습니다. 최종 패키지와 상세 체크 범위는 [QA 보고서](QA_REPORT.md), [설치 안내](INSTALL.md), [빌드 안내](BUILD.md)를 함께 확인합니다.

## 남은 제한과 배포 상태

- 바닐라 나침반 목표를 정식 Script API로 직접 변경하지 않습니다. 자체 32프레임 대안으로 프레임 선택의 최대 각도 오차는 5.625도이며, 원본의 연속 회전과 완전히 같은 외형·움직임은 아닙니다.
- 요새 안내·도착 영역은 제공 월드의 기반 시드에 한정됩니다. 다른 시드에 `.mcaddon`을 적용하면 요새 힌트를 꺼야 합니다.
- 소집 안전 검사는 보수적이므로 일부 실제로 서 있을 수 있는 특수 바닥도 거부할 수 있습니다. 소집 획득 OFF는 정적 제작법 제거가 아니라 사용 차단이며 이미 제작한 재료를 자동 반환하지 않습니다.
- **26.62 직접 실행, 3~4인 친구 초대 멀티플레이, FPS·TPS 실측은 미검증**입니다. 실제 다중 기기 차원 이동·소집·재접속·강제 종료 회귀도 완료하지 않았습니다.
- 이 문서 작성 시점에는 GitHub 커밋·Pull Request·Actions·병합·릴리스 작업의 완료 결과를 기록하지 않았습니다. 해당 작업을 수행한 뒤 실제 PR·Actions·릴리스 기록에서 결과를 확인해야 합니다. 로컬 검사 통과를 GitHub 배포 완료로 표현하지 않습니다.

현재 배포 판정은 **Pre-release**입니다. 남은 실전 검증이 완료되기 전에는 Stable로 승격하지 않습니다.
